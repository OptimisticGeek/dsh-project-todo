# 需求真相源与防过时协议

本文件是技能 `project-todo` 的开工前置约束：**任务排期正确，不等于需求口径正确**。
`ptodo` 管「做什么」，`utp/docs/prd/README.md`（需求注册表）管「按哪句做」。两者都要查。

> **适用范围（跨工具/跨项目）**：本文件描述的是配了 `utp/docs/prd/README.md` 的项目。其他项目或工具里没有该注册表、或任务无关联 PRD 时，**三查整体跳过**，只写回
> `ptodo context decision <id> "无需求资产（<项目名>），按任务描述 DoD 执行"`，**不得因缺文档阻塞或报错**。缺文档 ≠ 需求已作废。

## 唯一入口

| 层次 | 唯一落点 | 用途 |
|---|---|---|
| 需求状态与清单 | `utp/docs/prd/README.md` §3 | 判断文档 `生效/参考/待确认/已取代/已作废/已归档` |
| 口径修订 | 同上 §6「修订记录（CR 台账）」 | 判断某条需求是否已被 CR 推翻 |
| 客户原文 | `开发计划/需求对齐表.xlsx` sheet03 | L0，客户没提的功能不进验收 |
| 基线 PRD | `utp/docs/prd/智能体低代码与RAG实训模组-需求对齐与实施建议.md` | 必须连同头部「修订状态块」一起读 |
| 交付事实 | `utp/docs/version/x.y.z.md` + `VERSIONS.md` | 实测结论优先于任何设计文档 |
| 任务状态 | `docs/ptodo/todos.json`（`ptodo`） | 只管排期，不承载需求正文 |

**权威层级**：L0 客户原文 > L1 基线+CR > L2 ADR/批次计划/口径确认函 > L3 派生件（TODO 清单、看板、xlsx） > L4 版本文档（实测优先）。
同层冲突取生效日期新者；**不能裁决 → `ptodo task block <id> --reason "..."`，等书面确认，禁止自行择一**。

## G0.5 开工三查（在 `task start` 之后、改文件之前）

1. **查状态**：任务关联的需求文档在注册表 §3 里状态是什么？
   命中 `已取代` / `已作废` / `已归档` → **立即停止**，不采纳其 DoD，改按注册表指向的现行文件。
2. **查 CR**：§6 修订记录里有没有命中该需求的 CR？
   有 → 用「新口径」列，不用原文；正文里带 `⛔ CR-xxxx` 锚点的句子一律视为历史。
3. **查实测**：`utp/docs/version/` 最新版本文档对该能力的实测结论是什么？
   与 DoD 不一致 → **以版本文档为准**，先写回决策再动手。

> 三查结果写进任务上下文：
> ```bash
> ptodo context decision <id> "G0.5 已查：注册表 R1 / CR-000x / 版本 1.0.xxx；DoD@R1"
> ```

不能裁决的口径分歧（如客户确认函未回执）→ `ptodo task block <id> --reason "等客户确认口径"`，不实现、不改证据帧。
**纯只读问答、以及不改代码/文档的运维动作可跳过 G0.5。**

## 过时判据（六条）

- **R1 编号**：用 `Txx` 或未被 `需求对齐表.xlsx` sheet02 收录 → 历史件。
- **R2 决策冲突**：出现 `CubeStudio` / `provider=cube` / `HAMi` / `MIG` / `JupyterLab` / `50 并行` / `Ollama LLM` / `DeepSeek` 且无废弃说明 → 取 L2 现行口径。
- **R3 版本标识**：只看注册表「状态」列，**不看文件名**；`-v2` / `_v2` / `-final` 不构成生效证据。
- **R4 状态戳**：文档头部缺「状态 + 版本 + 生效日期 + 上游依据」→ 未受控，不得作为开发依据。
- **R5 DoD 闭环**：完成判据与最新版本文档实测不符 → 以版本文档为准并提 CR。
- **R6 层级裁决**：按权威层级自上而下；仍冲突 → `ptodo task block`。

## 与 ptodo 的接口约定

1. **DoD 带版本**：任务完成判据标 `DoD@R<n>`，用 `ptodo context decision <id> "DoD@R<n>：..."` 写回；`ptodo task done --evidence` 前校验 DoD 版本与注册表 R 值一致。
2. **口径变更要广播**：CR 生效后，对受影响任务逐个写回 `context decision`（如「CR-xxxx 生效，DoD 改 R<n>」），**不许静默改文件**。
3. **客户确认闸门**：`utp/docs/dev/客户口径确认函-2026-11-02.md` 三问未回执前，相关任务 `ptodo task block --reason "等客户回执"`，不实现、不改证据帧。
4. **计划状态词表独立**：计划索引用 `待评审/已评审/进行中/已收口`；任务用 `未开始/进行中/阻塞/已完成/已取消`（ptodo 状态）；需求文档用六值状态词表。**三套词表不可混用**。

## 禁止

- 禁止在 xlsx / CSV / 会话内 todo / 对话里新增或「顺手修正」需求条目；
- 禁止用 `xxx-v2.md` / `-final.md` 另存表示新版本；新版本 = 同一路径 + 新状态戳 + CR 记录；
- 禁止物理删除需求文档（历史口径是争议回溯凭据）；清理只做「标记 → 隔离归档（需确认）」；
- 禁止把本报告/演示产物当作需求来源。
