## 一、变更摘要

**需求**：待办界面在检测到用户首次安装时给一个按钮，一键把 `project-todo` 技能软链给本机已安装的
Claude Code、Codex、WorkBuddy、ZCode、Trae 等 Agent 工具。

实现：

- **共享核心** `lib/skills.js`：目标表（project / claude / codex / workbuddy / zcode / trae / dsh / agents）、
  状态判定（linked / copy / drift / foreign / missing）、安装（Windows junction，失败回退复制）、
  批量安装与移除、首次安装判定（有工具被检测到且尚未安装任何目标）。
- **CLI** 改为调用共享核心，新增 `trae` 目标，行为与 Web 完全一致。
- **Host API** `GET/POST /api/dsh-project-todo/skills`：
  - GET 返回 `source / firstRun / targets[]`（含 `label / path / state / detected / note`）；
  - POST 支持 `action: install|remove` 与 `targets[]`，未知目标返回 `INVALID`，单个目标失败不阻断其余。
- **Client**：
  - 首次进入且命中 `firstRun` 时，页面顶部出现「一键安装到已检测工具」，安装完成后自动消失，
    「稍后」会写入 `localStorage` 不再打扰；
  - 工具栏新增「技能」按钮，随时打开面板查看每个目标的状态（含 Trae 的手动导入提示）。

## 三、风险与待办

- **Trae**：其 Skill 目前主要通过 Settings → Rule & Skills 导入，是否扫描 `~/.trae/skills` 取决于版本；
  UI 已标注该提示，未验证的版本会显示为「已安装但需手动导入」。
- 安装动作会写用户主目录下的 skills 目录；共享 `/api` 通道已由载体做会话认证，POST 额外要求面板请求头。
- 目前不提供「自动在首次加载时静默安装」：必须由用户点击，避免未经同意修改主目录。
