## 一、变更摘要

**背景（用户反馈）**：待办页选「最近更新」/「创建时间」时列表几乎不动，看起来仍在按优先级排。

**根因**：排序只对 `visibleRoots` 生效，但分组视图随后把已排序的任务按里程碑/阶段重新分桶，
组的顺序仍取组织顺序（`order`）。阶段多、每阶段只有 1–3 条任务时，整页行序几乎不变；
真实看板上「最近更新」的行序与「优先级」逐条相同。

**修复**：

- 新增 `comparatorFor(sort)`，排序键比较器与 `sortTasksFor` 共用一份；
- `buildGroups` 在时间排序（`updated` / `created`）下同时排序层级：里程碑/阶段按
  「组内排序键最靠前的那条任务」（已排序 roots 的首条）比较，组内任务保持该键排序；
- `default` 收件箱（里程碑/阶段）在两种模式下都置底，保持 SPEC 既有约定；
- 「优先级」排序保持组织顺序（`order`）不变，不改变原有分组阅读顺序。

## 三、风险与待办

- **里程碑顺序会随时间排序变化**：这是有意行为（选择时间排序即按时间组织），但项目阶段的计划顺序
  在「最近更新」下会被打乱；若用户希望里程碑顺序固定、只排阶段与任务，可再调整（待确认）。
- 客户端 bundle 在 DSH 启动时快照：本地改完需刷新页面（HMR 生效时自动）或重启 DSH 才会看到新行为。
- 本次已提交；如需发布按仓库约定补 tag 与推送。

## 四、同版补充：默认排序改为「最近更新」倒序

- **口径**：面板排序下拉默认值由 `priority` 改为 `updated`（`client.js` 的 `sort` 初值）。`compareUpdated` 本来就是新→旧，因此默认即「按更新时间倒序」；用户仍可切「优先级」「创建时间」，切换只在当前会话生效，刷新回到默认。
- **与分组排序配套**：三、的时间排序同时作用于里程碑/阶段层级，因此默认视图就是「最近有变动的组排在最前」，`default` 收件箱仍置底。
- **测试**：`test/client.test.mjs` 的同名用例补两条默认态断言——默认渲染行序为 `A C B D`、下拉 `value === 'updated'`；显式切回 `priority` 恢复组织顺序 `B C A D`。`node --test` 全量 **183/183 通过**。
- **文档**：`SPEC.md` §7 排序条款、`docs/HELP.md` §12.1 补默认口径。
