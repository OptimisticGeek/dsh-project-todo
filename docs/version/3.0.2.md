## 一、变更摘要

**问题**：插件在别人的机器上反复出问题，根因不是某一个 bug，而是安装路径一直靠手改 profile：

- 旧 README 让人手工把包加进 `dsh.profile.bundles`、写 `link:E:/...` 这种本机路径；
- 一步写错就表现为「装了但没加载」「名字对不上」「旧版本仍在跑」，而且没有自检。

**修复（流程层，不动运行时代码）**：

- README 安装章节改为**一键安装**：`dsh plugin --profile <name> add github:OptimisticGeek/dsh-project-todo`
  （或本地绝对路径），并明确「不要手工编辑 `dsh.profile.bundles`」；
- 新增 [docs/INSTALL.md](../INSTALL.md)：环境矩阵（桌面壳 / `dsh web` / 纯终端）、
  一键安装与升级、`/health` 自检字段解释、卸载、症状 → 原因 → 处理 排障表、
  以及本插件依赖的 DSH 契约清单；
- `package.json` 增加 `engines.dsh: ">=0.1.5-rc.2"`：DSH 的插件管理器在安装时校验 DSH 版本，
  不兼容会在安装期报错，而不是运行时 404；
- README 文档地图补 `docs/INSTALL.md`。

## 二、验证与证据

- `node --test "test/*.mjs"`：143/143 通过（本次只改文档与清单，无运行时改动）。
- 安装命令行为依据 `@deepseek-ai/dsh` 的 `lib/plugin-*.js`：
  `reconcilePlugins()` 在 pnpm 成功后读取 profile 依赖、对声明了 `dsh.bundle.patch` 的包
  自动追加到 `dsh.profile.bundles`，随后写回 profile manifest —— 因此无需手工登记。
- 版本与健康检查：`health.version` 现为 `3.0.2`。

## 三、风险与待办

- 已安装 3.0.0/3.0.1 的用户升级时，包名已从 `@local/dsh-project-todo` 改为 `dsh-project-todo`：
  需先用 `dsh plugin --profile <name> remove` 旧包名或手工清掉旧 bundles 条目，再加新包，避免同名双份。
- `engines.dsh` 只影响 DSH 插件管理器（市场）安装路径；`dsh plugin add`（pnpm）不校验它。
- 尚未发布 npm：GitHub 安装是当前唯一一键路径；发布后可简化为 `add dsh-project-todo`。
