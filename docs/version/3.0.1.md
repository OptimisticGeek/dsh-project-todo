## 一、变更摘要

**问题**：部分环境（旧构建 / 精简 profile / 新装用户）没有 Host 的 `workingDirectory` 服务，
`resolveProjectRoot` 直接抛 `NO_PROJECT: workingDirectory 服务不可用，无法解析项目目录`，
待办页整体打不开——但这与「项目有没有初始化待办资源」无关。

修复：

- `lib/project.js` 新增 `sessionCwdOf(ctx, session)`：优先 `workingDirectory.get(session)`，
  该服务缺失或抛错时回退到 `session.header.cwd`；两者都没有才报可执行的 `NO_PROJECT`。
- `resolveProjectRoot` 改用回退链；错误文案改为「请在会话中打开一个项目目录」。
- `lib/http.js` 的 `sessionCwd`（用于完成版本解析）复用同一回退；
  `/health` 的 hint 区分「缺 agents（阻断）」与「缺 workingDirectory（已回退，仅提示）」。
- 文档明确：**新项目不需要预建 `docs/ptodo`**，空看板可正常打开，首次写入才创建数据文件；
  空项目 `getState` 已实测返回 `ok:true`、0 条任务。

## 二、验证与证据

- `node --test "test/*.mjs"`：**143/143 通过**。新增：
  - `test/project-fallback.test.mjs`：无服务时用会话头、服务优先于会话头、看板优先于 git 根、
    全无目录时报可执行错误、服务抛错时回退；
  - `test/http-host-half.test.mjs`：缺 `workingDirectory` 时 `/health` 提示回退，
    且 `/state` 通过会话头解析项目并返回 200。
- 空项目 `getState`：`{ ok: true, tasks: 0 }`（无 `docs/ptodo` 目录）。

## 三、风险与待办

- 会话头 `cwd` 只在创建会话时记录；会话中途切换目录只能靠 `workingDirectory` 服务感知，
  缺服务时页面显示的目录可能滞后（hint 已提示）。
- 待办页对空项目显示空表格，未提供「一键 ptodo init」按钮；需要时可后续加空状态引导。
