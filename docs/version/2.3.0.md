## 一、变更摘要

**1）修复「待办页显示 404」的根因**

旧实现把 API 注册在 `ctx.webServer` 的 `/dsh-project-todo` 前缀路由上，客户端用同路径的相对 `fetch`。
Web 载体（浏览器 `http://127.0.0.1:<port>`）能命中；桌面壳载体（页面来自 `dsh-app://app/`）只分发
DSH 共享的 `/api` 通道，于是请求变成 `dsh-app://app/dsh-project-todo/state` → 壳返回 404。

修复：

- `lib/http.js` 新增 `registerConnectionRoutes`：把 9 个接口注册为 **`/api/dsh-project-todo/*` 精确 Fetch 路由**
  （`ctx.connection.fetch.register`，`requestBody: 'buffered'`），Web 载体与壳载体共用同一条通道；
  内部用内存 req/res 桥接复用原 handler，业务逻辑不复制。
- `index.js` 注入 `connection` 注册便携路由；旧的 `webServer` 前缀路由保留兼容（老宿主、已缓存页面）。
- `client.js` 的 `BASE` 改为 `/api/dsh-project-todo`。
- 不再依赖端口、origin 或注入 token；共享通道由载体完成浏览器会话认证。

**2）失败可诊断，不再静默 404**

- 新增 `GET /api/dsh-project-todo/health`：返回插件 `version`、`services{webServer,agents,workingDirectory}` 与 `hint`；
- 注册失败、令牌注入失败、`ui.enabled=false` 都打显式 warning；
- 页面收到「404 + 空响应」时提示「Host 半边未加载、路由未注册」，而不是裸的 `HTTP 404`；
- 排障表拆成「接口没注册」与「Host/Client 版本不一致」两行（README / HELP）。
